## Search and source-ID capability contract

The general `GET /taxa?q=...` route currently searches `core.taxon.canonical_name` and `common_name`; source inspection does not show accession, collection, ticker, token, or DNA-sequence search in that query. It also supports explicit `source`, `rank`, `prefix`, kingdom, lineage, IDs, sort, and count/pagination. The native `GET /taxa/collections/fungip?q=...` is a separate FungiP collection index that can search collection names/IDs, DNA accession and curated ticker/launch identifiers when its qualified collection tables exist. It is not a database-wide accession or token index and its collection/launch facts are not canonical taxonomy facts.

Both route sources return limit/offset and a total for the same filter predicate; the FungiP collection route also reports linked, unresolved and ambiguous counts. These are source-level response contracts only. They do not verify that a particular deployed build produced the reported browser totals.

The native `GET /genetics?search=...` searches sequence species name, gene, and accession. Exact `taxon_id` filtering and returned linkage UUID are supported by this source snapshot. The sequence DTO now exposes accession.version and taxon UUID on list and stored-accession reads. An explicit `POST /genetics/ingest-accession` also uses the exact NCBI taxid crosswalk before storing a fetched record; a missing or ambiguous crosswalk leaves `taxon_id` null and the reason in metadata. This can locate a stored sequence accession; it does not prove the accession belongs to a canonical taxon unless an exact crosswalk is present. A separate Database-owned frozen reference-sequence BFF/workbench remains the accession-search/import lane; this MINDEX change does not duplicate that interface or claim its real data is canonically linked.

`GET /genetics?taxon_id=<uuid>` and `GET /genetics/accession/<accession>` are source-level stored reads. `POST /genetics/ingest-accession` is a separate provider-fetch/database-write operation and is outside this qualification. Taxon detail `GET /taxa/<uuid>` defaults `read_only=false` in this source snapshot and can schedule an incomplete-taxon queue task; callers requiring a pure read must set `read_only=true` and still qualify the deployed build. The broad `/unified-search` GET contract is version-sensitive and can have cache/event/sync/persistence effects; do not treat it as a no-write endpoint without a service-version receipt.

No universal collection-ID, ticker, token, or accession identifier table is established by this patch. For root's reported browser examples—Amanita page 12 (`50 of 1515`), collection `FG032` (one match), and query `Schizophyllum` (49)—the endpoint, build, selector, exact response and complete-total receipt were not supplied to this native worktree. They are owner-reported observations only. Do not use them as proof of a deployed MINDEX contract or merge their counts with a different route's results.

### Real-input parser validation

On 2026-10-03, a bounded GET to [NCBI GenBank LT627806.1](https://www.ncbi.nlm.nih.gov/nuccore/LT627806.1) returned 4,900 bytes (SHA-256 `f14eff4e61bdf34051ef380e1cccce0b18d2a3511b1055a78439d5127e314b7f`). The source parser returned one record: primary accession `LT627806`, accession.version `LT627806.1`, organism `Pleurotus ostreatus`, source taxon ID `5322`, and the versioned NCBI URL. NCBI Taxonomy identifies taxid 5322 as *Pleurotus ostreatus* ([taxon 5322](https://www.ncbi.nlm.nih.gov/Taxonomy/Browser/wwwtax.cgi?id=5322&mode=info)); splitgill *Schizophyllum commune* is taxid 5334 ([taxon 5334](https://www.ncbi.nlm.nih.gov/Taxonomy/Browser/wwwtax.cgi?id=5334&mode=info)). This corrects a misleading synthetic unit-test UUID pairing. The importer tests now use an explicitly synthetic exact crosswalk UUID and do not claim the live crosswalk exists. No NCBI taxon was assigned to the splitgill UUID, and no MINDEX database was queried.

## Source changes in the candidate

- `mindex_etl/sources/genbank.py`: preserve accession.version, all unique numeric `taxon:` cross-references and versioned source URL; refuse a singular ID when the record contains conflicting taxon IDs.
- `mindex_etl/jobs/sync_genbank_genomes.py`: resolve only a unique exact NCBI external-ID crosswalk for both genomic-sequence and ITS records; persist linkage state/source IDs/version; update existing ITS rows; count only inserted rows. Existing `0012_genetics.sql` already has optional taxon FK and sequence version, so this path introduces no migration.

- `mindex_api/routers/genetics.py`: return 503 for a missing/unverifiable sequence schema instead of a misleading not-found/empty interpretation; expose accession.version and canonical taxon UUID and use an exact NCBI crosswalk in the explicit accession-ingest POST.
- `mindex_api/routers/compounds.py`, `mindex_api/schemas/compound.py`: return stored compound and association citations/identifiers without creating evidence; wrap exact read schema/query failures as 503.
- `mindex_api/routers/all_life.py`: exact linked images with required attribution schema; explicit 503/readiness states for images, interactions and publications; preserve directional relationship endpoints; report publication association provenance as not recorded by the present link schema.
- `mindex_etl/sources/inat.py`, `mindex_etl/taxon_canonicalizer.py`: keep text with unverified licensing as a provenance-bearing candidate and merge metadata without dropping existing evidence.
- `mindex_etl/sources/inat.py`: normalize only exact numeric iNat taxon/photo identities; record provider URLs, attribution and license code, and keep the candidate unpublished for a separate rights review.
- `mindex_etl/sources/wikipedia.py`: exact page-summary fetch requires an iNat-provided page URL plus expected page ID, pins the returned revision, and withholds publication while revision-specific license evidence is missing.
- `mindex_etl/sources/wikimedia_commons.py`: exact Commons file page ID normalizes the source file URL, license, creator/attribution, and response/normalization hashes; missing attribution blocks reuse.
- `mindex_etl/sources/publication_evidence.py` and `mindex_etl/jobs/import_taxon_publication_evidence.py`: parse one exact GenBank accession.version; reject direct submissions and wrong/ambiguous source taxon crosswalks; stage immutable source-attested evidence candidates without creating reviewed publication links.

- `migrations/20261003_publication_taxon_evidence_OCT03_2026.sql`: additive evidence-table contract with source and normalization hashes, candidate/terminal review states, identity uniqueness, immutable-source trigger, reviewer-required disposition and ETL grants. Cursor apply remains pending.
