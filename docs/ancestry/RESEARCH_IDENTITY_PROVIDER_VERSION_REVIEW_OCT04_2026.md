### BOLD

The local output inventory contains no retained BOLD source response or BOLD-specific stored metadata projection. BOLD's official FAQ describes Process IDs as record identifiers and its sequence-submission handbook allows replacing a sequence under the same Process ID or Sample ID. See [BOLD Process ID FAQ](https://v3.boldsystems.org/index.php/resources/boldfaq?chapter=2_BolduserQuestions.html&section=q1) and [BOLD sequence replacement guidance](https://v3.boldsystems.org/index.php/resources/handbook?chapter=3_submissions.html&section=sequence_uploads). A Process ID therefore does not establish an immutable sequence version. BOLD stays `version_namespace_unsupported`; a content hash alone is a local byte identity, not a provider-assigned revision.

### UNITE

No retained UNITE source response or UNITE-specific `bio.genetic_sequence.metadata` mapping was found in the inspected evidence. UNITE's official documentation says a Species Hypothesis accession includes its own version component and taxon acronym, and that SH accessions have stable DOIs and link across release versions; the representative/reference sequence is a separate identity relationship. See the [UNITE FAQ](https://unite.ut.ee/faq.php) and [UNITE resource/release formats](https://unite.ut.ee/repository.php). Without a retained source row showing whether MINDEX's `accession` is the SH, a UDB/INSDC sequence, or another sequence identifier—and how its exact sequence bytes relate to that SH—the exporter cannot map the SH version into `bio.genetic_sequence.version`. UNITE remains `version_namespace_unsupported`; a catalog-wide release number is not used as a per-row version.

## Portable Cursor acquisition and qualification plan

All steps below are for Cursor to execute only after selecting an approved source record and a read-only authority. They do not request a shared-database write, provider mutation, schema change, or deployment.

1. **Ensembl stable-ID case:** select a real `ENSG`, `ENST`, `ENSP`, or other Ensembl stable identifier already present in the target stored row. Capture the raw JSON response, HTTP status/headers, requested URL/type, retrieval UTC, and pinned Ensembl release/assembly from `GET https://rest.ensembl.org/sequence/id/{stable_id}?content-type=application/json` (use an explicit `type=protein`, `cdna`, `cds`, or `genomic` where applicable); capture `/lookup/id/{stable_id}?content-type=application/json` alongside it to bind feature type and assembly. Preserve exact response bytes and SHA-256 externally. Compare response stable `id` to `accession`, integer stable-ID `version` to the stored version string, response `molecule` to the exact stored molecule class, and SHA-256 of response `seq` UTF-8 bytes to the read-only database-computed sequence digest. Do not equate current release, assembly, display name, or stable ID alone with the stable-ID version. If the stored sequence type cannot distinguish the requested Ensembl sequence type or any field/hash is absent or mismatched, retain the row as unavailable/partial and do not promote it.
2. **BOLD case:** use the official approved public-data export for one exact Process ID, preserve the query/preprocessor response, query token, raw downloaded JSON/BCDM record, HTTP metadata, and retrieval time. Preserve the Process ID, marker, exact sequence and hash, and all provider-supplied revision/release fields verbatim. The official [BOLD Portal API](https://portal.boldsystems.org/api) documents the query token as a short-lived download handle; the record Process ID can survive sequence replacement. Verify from the captured record or provider documentation whether any immutable sequence revision exists. If no provider-native immutable revision is supplied, keep the version namespace unsupported and offer only a separately typed captured-snapshot identity for review.
3. **UNITE case:** acquire one official release package with its DOI/release manifest and checksums; retain the exact FASTA header and sequence bytes plus the matching taxonomy/SH metadata row. Determine whether the stored row accession names the SH accession or a representative/reference/UDB/INSDC sequence, and preserve the explicit relation among those identifiers, the SH's embedded version, marker/type, and exact sequence hash. Admit a version only if the source record proves a one-to-one identity/version/type and its sequence hash matches the database row; otherwise keep it unsupported. Do not substitute the global UNITE release number, SH taxon mapping, or representative sequence for the stored row's own identity.
